## Kraken spot market discovery (paper-only)

`market_discovery.py` parses public Kraken `Assets` and `AssetPairs` responses, normalizes known asset aliases, records Decimal order/cost minimums and increments, and explains exclusions. Only the exact `AssetPairs` result key (Kraken pair ID) may be listed in an eligibility confirmation. Alternate pair names, websocket names and a shared base/quote symbol do not authorize a pair.

An `EligibilityConfirmation` is caller-supplied policy metadata, **not Kraken authorization evidence**: the module does not authenticate the account or query whether Kraken permits that account to trade. Populate it only after an authorized compliance/account owner verifies current product eligibility from an authoritative Kraken source tied to the exact account (or a formal internal determination backed by that source). Record the non-secret account scope, evidence/ticket reference, reviewer and review time; never store API credentials in this policy. The code checks that metadata and expiry but cannot independently validate the source or account entitlement.

Missing, null, empty, unknown or ambiguous asset identifiers, invalid trading rules, suspended products, margin/derivative products, unconfirmed pairs, expired snapshots and failed refreshes all fail closed. This is metadata discovery only; execution remains simulated and Kraken order placement, withdrawals and deployment are out of scope.

## Kraken spot market discovery (paper-only)

`market_discovery.py` parses public Kraken `Assets` and `AssetPairs` responses, normalizes only known asset aliases, records Decimal order/cost minimums and increments, and reports reasons for excluded pairs. Missing, null, empty, unknown, malformed or ambiguous base/quote identifiers fail closed. Public exchange status is not UK account eligibility.

`EligibilityConfirmation` is only an application policy assertion supplied by the caller; it does not query Kraken, authenticate a key, or prove that Kraken has authorized that account to trade. Populate it only after an authorized compliance/account owner verifies current product eligibility from an authoritative Kraken source tied to the exact account (or a formal internal compliance determination backed by that source). Store a non-secret account scope, evidence/ticket reference, reviewer and review time; never use API credentials as the account identifier. A generic public market list, cached configuration, or confirmation for a different Kraken account is insufficient. The code checks the supplied scope metadata and expiry but cannot validate the source or account authorization independently.

Market snapshots expire and a failed refresh clears the former eligible set. This is metadata discovery only; execution remains simulated and Kraken order-placement, withdrawal and deployment are out of scope.
